## 2026-09-10 - [CRITICAL] Prevent Disabling SSL Verification Fallbacks
**Vulnerability:** The application was catching `requests.exceptions.SSLError` and explicitly retrying the HTTP request with `verify=False`. This effectively bypassed SSL verification when the remote server presented an invalid or untrusted certificate, opening the application up to Man-in-the-Middle (MitM) attacks where an attacker could intercept and potentially alter the downloaded data.
**Learning:** Hardcoding fallbacks that compromise security to improve "reliability" creates critical vulnerabilities. External requests, especially those retrieving data over the internet, must always strictly enforce SSL certificate verification.
**Prevention:** Never use `verify=False` in HTTP clients like `requests`. Always enforce `verify=True` (or omit the parameter to use the default secure behavior) and handle SSL verification errors gracefully by failing the operation securely, logging the error appropriately without exposing sensitive information, rather than trying to bypass the security check.
