## 2026-09-05 - Insecure SSL Verification Fallback in HTTP Requests
**Vulnerability:** The application was catching `requests.exceptions.SSLError` and explicitly falling back to making requests with `verify=False` when downloading files from the ANP website.
**Learning:** This implementation explicitly bypassed a fundamental security mechanism designed to prevent Man-in-the-Middle (MITM) attacks. If the target server had an invalid or expired certificate, or if an attacker was intercepting the traffic, the app would quietly accept the insecure connection, potentially allowing malicious data to be downloaded and processed. It highlights a dangerous anti-pattern where functionality/resilience is prioritized over critical security guarantees.
**Prevention:** Never use `verify=False` in production code when communicating over HTTPS, even as a fallback mechanism. Instead, handle SSL errors gracefully by logging the failure, alerting the team, and failing securely rather than proceeding over an untrusted connection. Any certificate issues must be fixed on the infrastructure/server side, not bypassed in the application code.
